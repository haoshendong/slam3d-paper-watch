方法本质拆解 · What actually changed

是不是微调？

是完整后训练，不是推理时技巧。先对 Qwen3.5-4B 做全参数 SFT（视觉塔冻结），再用多轮 RL 更新策略；critic 单独训练并在每轮后更新。SFT 数据由 GPT-6 Astra 等生成，RL 的 rollout 在仿真 harness 内完成。

有没有额外约束？

动作空间被严格限制为 22 个低层原语加 finish()，每个 move_to 转成直线笛卡尔运动并做 IK、自碰撞与逐子步力监控；SFT 还把历史坐标以 0.2 概率替换为 mask，强制模型看当前图像。RL 的回报含 finish 成功、预算耗尽、false finish 等分段值。

推理/后端到底做了什么？

测试时策略只看相机图像与 receipt，按 ReAct 循环最多 60 个请求写 Python 并执行；critic 被移除，不使用特权状态、VLA 或前沿模型。单集平均 32.6 个请求、16.6 个物理动作、7.3k 输出 token，约 52 GPU-秒。

方法本质是什么？

本质是“把操作策略变成对低层 API 的程序生成”，再用仿真特权物理状态给多轮程序分配信用。它改变的是策略的输出形式（代码）与训练信号（按物理状态变化分摊），没有改变的是底层运动仍由受控笛卡尔原语执行。

输入（图像 + 任务说明 + receipt 历史）→ 4B VLM 写 Python 调用 22 个低层原语 → 仿真 critic 按物理状态变化给每个请求分配信用 → SFT+多轮 RL 得到可独立部署的 CaP 策略。

01

桥接价值Bridge

桥接价值

空间推理要落到具身决策，中间缺的往往不是更大模型，而是“把感知/几何结果变成可执行、可验证动作”的接口。CaPtain 的 harness 只给低层原语和结构化回执，强制策略自己做抓取点、接近方向与夹爪时机决策，这比调用 grasp/place 技能更接近真实具身推理。它的 critic 设计也提示我们：在多步几何/定位流程里，可以用“物理状态变化”而不是文本 token 来分配信用。

02

方法与模块Method

方法摘要

策略是 Qwen3.5-4B，harness 暴露 22 个能力：observe、segment（SAM 3）、point（Molmo2）、mark_point、track_target、几何测量、move_to、hold、recover、release、可达性/时序检查等，没有 grasp/place 技能，也没有 VLA。每个请求是一段 Python cell，执行后返回结构化 receipt（停止原因、执行距离、峰值力、夹爪开合）与最多 4 张图；上下文按 turn 压缩，但 Python 变量跨请求保留。SFT 用 GPT-6 Astra 生成的 25,961 条轨迹（861M token），只监督 agent 产生的 token；RL 用 5 个 MLP 集成的 critic 读取 36 维特权物理特征，按 δ_t=c_t+V(s_{t+1},t)−V(s_t,t) 给每个请求分配信用。

可迁移模块

第一是“低层原语 + 结构化回执”的 harness 设计：把感知、几何测量、受控运动拆成可组合 API，策略只能通过这些 API 行动，便于审计与复现。第二是固定时间索引的 TD 信用：V(s_{t+1},t)−V(s_t,t) 让纯感知请求天然得到接近 0 的信用，这一招可以直接搬到多步标定/建图流程。第三是特权 critic 的特征分组与“排除策略行为计数”的消融，避免了时间泄漏。

04

边界与下一步Limits & Next Step

边界与风险

最大边界是训练分布：RL 只在 40 个 LIBERO 单臂任务上做，双臂协调与陌生 6-DoF 臂的运动学是主要失败源（RoboTwin 22.6%、RoboDojo 0.8%）。critic 依赖精确仿真状态；作者自己的敏感性实验显示，2 cm 位姿噪声把与特权 ΔV 的相关性降到 0.49，5 cm 降到 0.36，用策略自身感知只有 0.21，因此真机在线 RL 需要额外状态估计。接口也限定了能力上限：22 个受控笛卡尔原语无法表达持续力控（如 Wipe）。

下一步实验

第一步把 critic 的信用分配搬到我们的多步定位/标定流程，用“位姿误差或约束残差变化”代替特权状态，先做离线回放验证。第二步在双臂或移动平台上测试原语扩展：增加底盘速度、云台、双臂协同原语，观察是否只是接口不足而非策略不行。第三步做“特权状态噪声”鲁棒性曲线，确定在什么位姿精度下 critic 仍能工作，为真机部署设定门槛。

原文摘要 · Abstract

代码即策略（CaP）让模型写程序调用机器人 API，但现有系统要么在测试时调用闭源前沿模型，要么把操作外包给预训练 VLA，小型开源 VLM 直接失败。CaPtain 给出一条完整的 SFT 加多轮 RL 后训练流水线：在只暴露 22 个低层感知/几何/受控运动原语的 harness 内，先用 GPT-6 Astra 生成的轨迹做 SFT，再用读取仿真特权物理状态的 critic 做多轮 RL，把稀疏的终局结果分摊到具体请求。4B 模型在 LIBERO 上从 0 升到 55.4%（SFT）再到 73.8%（RL），LIBERO-PRO 达 78.5%。

Across coding, web, and tool-use tasks, language-model agents are now routinely trained with the same recipe: supervised fine-tuning (SFT) to learn the interface, then multi-turn reinforcement learning (RL) to master it. Code-as-policy (CaP) casts robot manipulation in the same form, as the policy writes code against robot APIs and reads back the results, so the same recipe should apply. Yet existing CaP agents sidestep training: they either prompt closed frontier models or delegate manipulation to pre-trained vision-language-action models (VLAs) and high-level skills, while small open vision-language models (VLMs) fail outright. We present CaPtain, an open post-training pipeline that turns a small open VLM into a capable CaP agent, with no VLA, frontier model, or privileged state at test time. CaPtain trains and deploys the policy inside CaPtain-Harness, which exposes low-level perception, geometry, and guarded-motion primitives across simulation and real hardware. We first align the base model via SFT on synthetic trajectories generated with GPT-6 Astra, then apply multi-turn RL. Multi-turn RL must credit tens of agent requests, whose physical effects often surface turns later, from a single end-of-episode outcome. We therefore introduce a physical critic that reads privileged simulator state, never seen by the policy, and credits each request by how much it changes the predicted chance of success. Starting from Qwen3.5-4B (0% zero-shot), CaPtain-4B reaches 55.4% held-out LIBERO success after SFT and 73.8% after RL. On LIBERO-PRO, it reaches 78.5%, surpassing several frontier-model agents, and its RL gains persist across three perturbation suites (+17.6 to +21.2 points). Without target-domain training, it attains 83.3% on SimplerEnv WidowX, exceeds frontier models on CaP-Bench, and runs on a real robot after simulation-only adaptation. We release all code, data, and model weights.
